# Методология — Qazaq Loc QA

Отчёт для жюри о прогоне `locqa` на файлах из `grand-loc-qa-handout-2026-10-27`. Сами данные партнёра в репозитории не хранятся, здесь только описание и цифры.

## 1. Данные

| Файл | Строковых ключей | Особенности |
|---|---|---|
| intl_ru.arb | 5479 | 133 маркера `@@comment`, 6 дублирующихся ключей |
| intl_kk.arb | 5469 (уникальных) | 109 ключей объявлены повторно, у 10 из них значения разные; 2 ключа отсутствуют в ru |
| intl_uz.arb, intl_en.arb | — | используются как референсы для `wrong_language` |

Из повторяющихся `@@comment` и дублей ключей следуют два решения. Строгий JSON-парсер оставляет последнее значение, поэтому:

- инструмент читает файл с учётом всех вхождений ключа;
- `apply` правит файл текстово: порядок, отступы, все `@@comment` и все вхождения изменённого ключа сохраняются.

Конфликтующие дубли выводятся в `diagnostics` вместе со всеми значениями.

## 2. Как искали ошибки

Проверки организованы в четыре слоя: правила → статистика самого файла → LLM → человек. Детали каждого типа описаны в [README](README.md#методология).

- **Детерминированные правила.** Отсутствующие или пустые строки, ICU и плейсхолдеры (`{name}` и printf `%s`/`%d`), аффикс сразу после плейсхолдера, смешение кириллицы и латиницы внутри слова, узбекские буквы ў/ҳ, совпадение с uz/en-файлами.
- **Статистика по файлу.** Пороги длины считаются от медианного соотношения kk/ru. Опечатки ловятся сравнением частот: «сагат» встречается 1 раз, а «сағат…» — 19. Устойчивые переводы терминов (`inconsistent_term`) и ассоциации слов ru↔kk (проверка смысла) тоже считаются по самому файлу.
- **Калибровка по реальному файлу.** На этих данных первый прогон дал 750 находок при ~100 подложенных ошибках. Разбор показал источники шума, и правила были исправлены:
  - казахская запись «{n}-орын» / «5-күн» — норма, а не ошибка аффикса;
  - «Telegram-ды», «PvP-де» — латинское имя с казахским аффиксом через дефис, это норма;
  - казахский перевод естественно вдвое длиннее короткого русского ярлыка;
  - одиночные совпадающие с русским существительные почти всегда заимствования (Энергия, Фестиваль);
  - синонимы в длинных фразах не считаются несогласованностью терминов.

  Итог: 132 находки при пороге confidence ≥ 0.5 и ещё 229 ниже порога (доступны через `--all`).
- **Подозрение на неверный смысл** (`adequacy`) — экспериментальная проверка. Казахское слово, которое во всём файле переводит другое русское слово и не связано ни с одним словом исходника, выдаётся как лид, например «Зелья → Жер». Precision у неё низкая, поэтому её находки идут с confidence 0.45 и в отчёт по умолчанию не попадают.

**Что сознательно не использовалось.** В `intl_kk.arb` есть артефакты форматирования, например нестандартные отступы у части строк. Они, вероятно, совпадают с местами подложенных ошибок. Инструмент должен работать на любом ARB, поэтому такие признаки в детекции не применяются.

## 4. Как исправляли

1. `export-review` строит `review_kk.csv`. В нём 130 строк по находкам инструмента и 20 строк, добавленных при ревью.
2. **LLM-ревью.** Его выполнил LLM в этой сессии; носителя казахского в команде не было.
   - **109 исправлений** по находкам инструмента. Плейсхолдеры и аффиксы правились по правилам. Узбекский, португальский и русский текст переведён на казахский. Добавлены непереведённые строки и обрезаны хвосты вроде «…туралы толық ақпарат алу үшін». Термины выровнены по преобладающему в файле варианту.
   - **21 находка признана ложной** с объяснением: имена собственные, допустимые заимствования, фрагменты фраз, корректные перефразировки.
   - **20 смысловых ошибок найдено вручную** среди подсказок ниже порога и при сверке с en-файлом. Примеры:
     - «Брак» → «Заңға бағынушылық» (перевод от «Законопослушность»), исправлено на «Неке»;
     - «Цвет фар» → «Бағдаршамның түсі» (светофор), исправлено на «Фаралардың түсі»;
     - «Зелья» → «Жер» (земля), исправлено на «Зельелер»;
     - «Баланс» → «қолма-қол ақша» (наличные) в трёх ключах;
     - «Выбрать» → «Аймақты таңдаңыз» (выберите регион) в трёх ключах;
     - «Персонажи» → «Таңбалар» (символы).
3. `apply --include-unreviewed --suggested-by "LLM: LLM (без проверки носителем)"` собирает `intl_kk_fixed.arb`.
   - **129 изменённых строк.** У каждой стоят `"x-reviewed": false`, `x-suggested-by`, `x-original` и комментарий с обоснованием.
   - Все остальные строки файла не изменены байт-в-байт.
   - Файл проходит `locqa validate`: ICU корректен, плейсхолдеры совпадают с исходником.

Флаг `x-reviewed: true` **не ставился**: правки делал не человек. По правилам кейса такие строки не входят в оценку качества перевода. Если носитель проверит `review_kk.csv`, `scripts/run_pipeline.sh apply` пересоберёт файл с `"x-reviewed": true` у проверенных строк.

Массового перевода заново не было: изменено 129 строк из 5469, и у каждой есть находка или обоснование.

## 6. Стоимость LLM

- В этой сессии LLM-проход выполнен моделью LLM напрямую, без вызовов API из инструмента. Токены по этому проходу инструмент не измерял, поэтому цифру стоимости дать нельзя. Объём: 130 строк ревью, около 33 KB входного текста.
- Для воспроизводимого прогона через API используйте `locqa check --llm anthropic|openai --llm-scope flagged`. Стоимость попадёт в `report.json → llm.cost_usd`. Оценку объёма до запуска даёт `--llm-dry-run`.

## 7. Строки, требующие решения в коде или у носителя

- **Аффиксы после плейсхолдера.** 8 строк, все переформулированы без аффикса: например `{price}-ге сатып алу` → `{price} бағасына сатып алу`. Тег `needs_code_handling` стоит у числовых плейсхолдеров.
- **«Сезонный пропуск»** переведён в файле четырьмя способами: Сезондық пас / Мезгілдік пасс / Маусымдық пасс / маусымдық пропуск. Нужно единое решение, запись в глоссарии стоит в статусе `draft`.
- **Ставки:** «ставка» и «тігіс/бәс» используются в разных разделах.
- **`lnyHeader`:** в kk стоит «en». Возможно, это код языка, и должно быть «kk».

## 9. Ограничения

- `flutter gen-l10n` на итоговом файле не запускался: Flutter SDK нет в окружении разработки. Проверку выполняет CI-job и `scripts/check_gen_l10n.sh`.
