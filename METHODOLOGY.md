# Методология — Qazaq Loc QA

Отчёт для жюри о прогоне `locqa` на файлах из `grand-loc-qa-handout-2026-10-27`. Сами данные партнёра в репозитории не хранятся, здесь только описание и цифры.

## 1. Данные

| Файл | Строковых ключей | Особенности |
|---|---|---|
| intl_ru.arb | 5479 | 133 маркера `@@comment`, 6 дублирующихся ключей |
| intl_kk.arb | 5469 (уникальных) | 109 ключей объявлены повторно, у 10 из них значения разные; 2 ключа отсутствуют в ru |
| intl_uz.arb, intl_en.arb | — | используются как референсы для `wrong_language` |

Из повторяющихся `@@comment` и дублей ключей следуют два решения. Строгий JSON-парсер оставляет последнее значение, поэтому:

- инструмент читает файл с учётом всех вхождений ключа;
- `apply` правит файл текстово: порядок, отступы, все `@@comment` и все вхождения изменённого ключа сохраняются.

Конфликтующие дубли выводятся в `diagnostics` вместе со всеми значениями.

## 2. Как искали ошибки

Проверки организованы в четыре слоя: правила → статистика самого файла → LLM → человек. Детали каждого типа описаны в [README](README.md#методология).

- **Детерминированные правила.** Отсутствующие или пустые строки, ICU и плейсхолдеры (`{name}` и printf `%s`/`%d`), аффикс сразу после плейсхолдера, смешение кириллицы и латиницы внутри слова, узбекские буквы ў/ҳ, совпадение с uz/en-файлами.
- **Статистика по файлу.** Пороги длины считаются от медианного соотношения kk/ru. Опечатки ловятся сравнением частот: «сагат» встречается 1 раз, а «сағат…» — 19. Устойчивые переводы терминов (`inconsistent_term`) и ассоциации слов ru↔kk (проверка смысла) тоже считаются по самому файлу.
- **Калибровка по реальному файлу.** На этих данных первый прогон дал 750 находок при ~100 подложенных ошибках. Разбор показал источники шума, и правила были исправлены:
  - казахская запись «{n}-орын» / «5-күн» — норма, а не ошибка аффикса;
  - «Telegram-ды», «PvP-де» — латинское имя с казахским аффиксом через дефис, это норма;
  - казахский перевод естественно вдвое длиннее короткого русского ярлыка;
  - одиночные совпадающие с русским существительные почти всегда заимствования (Энергия, Фестиваль);
  - синонимы в длинных фразах не считаются несогласованностью терминов.

  Итог первой калибровки: 170 находок при пороге confidence ≥ 0.5.
- **Вторая калибровка (30.10).** Повторная проверка на файле выявила:
  - 12 ложных `glossary_violation`: «автокөлік» (синоним «көлік») и глагольные формы «жазылу/жазылғаныңыз» для «подписка» — добавлены в `kk_variants`;
  - ложный `machine_translation_suspect` на фамилии, скопированной из исходника («Вишневский»);
  - автопредложение для запрещённой формы теряло окончание («ойнаушыларды» → «ойыншы»); теперь «ойыншыларды»;
  - пропуск `length_overflow` в частях фраз (`summerRushRaceGasAfterPrefix`: «через:» → «кейін: режимін қосу және жалғастыру»);
  - `machine_translation_suspect` без LLM почти не срабатывал. Добавлен список «ложных друзей» машинного перевода (ставка → «тігіс», кейс → «іс», инвентарь → «түгендеу», персонаж → «таңба» и др.): правило срабатывает только при русском триггере в исходнике. **Список составлен по наблюдениям в этом файле**, это доменный словарь, а не универсальная модель.

  Итог: 180 находок в 171 ключе (59 high, 112 medium, 9 low) и 233 ниже порога (доступны через `--all`).
- **Подозрение на неверный смысл** (`adequacy`) — экспериментальная проверка. Казахское слово, которое во всём файле переводит другое русское слово и не связано ни с одним словом исходника, выдаётся как лид, например «Зелья → Жер». Precision у неё низкая, поэтому её находки идут с confidence 0.45 и в отчёт по умолчанию не попадают.

**Что сознательно не использовалось.** В `intl_kk.arb` есть артефакты форматирования, например нестандартные отступы у части строк. Они, вероятно, совпадают с местами подложенных ошибок. Инструмент должен работать на любом ARB, поэтому такие признаки в детекции не применяются.

## 4. Как исправляли

1. `export-review --suggestions out/suggestions.json` строит `review_kk.csv`: 171 строка по находкам инструмента. Предложения правок (`suggestions.json`, 145 ключей) подготовил LLM (Claude) в рабочей сессии; носителя казахского в команде не было.
   - Плейсхолдеры и аффиксы правились по правилам; аффикс переносится на слово-буфер («{min} мәнінен», «{provider} арқылы»).
   - Узбекский, португальский и русский текст переведён на казахский, добавлены непереведённые ключи, обрезаны дописанные хвосты вроде «…туралы толық ақпарат алу үшін».
   - Термины выровнены по преобладающему в файле варианту и глоссарию.
   - 33 находки помечены как вероятно ложные или требующие решения носителя (`suggestion: null`): имена, заимствования, фрагменты фраз, «тігіс» в разделе ставок, «сезонный пропуск» (draft).
2. `apply --include-unreviewed --suggested-by "LLM (Claude), без проверки носителем"` собирает черновик `intl_kk_fixed.arb`:
   - **134 изменённые строки**, у каждой `"x-reviewed": false`, `x-suggested-by`, `x-original`, `x-issues` и `x-review-comment`;
   - остальные строки не изменены байт-в-байт;
   - файл проходит `locqa validate` (ICU, плейсхолдеры совпадают с исходником). Повторный `check` по черновику: 40 находок, почти все — строки, сознательно оставленные носителю; одна новая — `userMenuReportsFromTo` стала длиннее из-за переформулировки без аффиксов.

Флаг `x-reviewed: true` **не ставился**: правки делал не человек, по правилам кейса такие строки не входят в оценку качества. Носитель заполняет `decision`/`reviewer` в `review_kk.csv`, затем `scripts/run_pipeline.sh apply` пересобирает файл с `"x-reviewed": true` у проверенных строк, а `check --review` переносит решения в `report.json`: отклонённые носителем (`keep`) находки уходят из отчёта, найденные при ревью — добавляются (`summary.review`).

Массового перевода заново не было: изменено 134 строки из 5469, у каждой есть находка инструмента.

## 6. Стоимость LLM

- LLM-проход выполнен моделью Claude в рабочей сессии, без вызовов API из инструмента. Токены инструмент не измерял, поэтому точной стоимости нет. Объём: 171 строка ревью, около 70 KB входного текста (`review_kk.csv`); при прогоне через `--llm anthropic` с ценами в `LOCQA_LLM_PRICE_*` стоимость попадёт в `report.json → llm.cost_usd`.
- Для воспроизводимого прогона через API используйте `locqa check --llm anthropic|openai --llm-scope flagged`. Стоимость попадёт в `report.json → llm.cost_usd`. Оценку объёма до запуска даёт `--llm-dry-run`.

## 7. Строки, требующие решения в коде или у носителя

- **Аффиксы после плейсхолдера.** 8 строк, все переформулированы без аффикса: например `{price}-ге сатып алу` → `{price} бағасына сатып алу`. Тег `needs_code_handling` стоит у числовых плейсхолдеров.
- **«Сезонный пропуск»** переведён в файле четырьмя способами: Сезондық пас / Мезгілдік пасс / Маусымдық пасс / маусымдық пропуск. Нужно единое решение, запись в глоссарии стоит в статусе `draft`.
- **Ставки:** «ставка» и «тігіс/бәс» используются в разных разделах.
- **`lnyHeader`:** в kk стоит «en». Возможно, это код языка, и должно быть «kk».

## 8. Глоссарий

`glossary.csv` содержит 40 записей:

- 5 терминов из брифа: фракция, семья, Grand Coins/GC, бизнес, варн;
- сленг игроков: варн, мут, фура, ГК;
- 30+ игровых терминов, выведенных из фактического употребления в файле. В `note` указано покрытие, например «В файле: 178/180 строк».

Статусы:
- `observed` — так переводит большинство строк файла;
- `from_brief` — правило из брифа (бренды не переводятся);
- `draft` — нужен носитель.

Полный список кандидатов (330) лежит в `term_candidates.csv`. Носителем записи пока не проверялись (0 из 40); статус `observed` означает «так в файле», а не «одобрено».

## 9. Ограничения

- `flutter gen-l10n` на итоговом файле не запускался: Flutter SDK нет в окружении разработки. Проверку выполняет CI-job и `scripts/check_gen_l10n.sh`.
- **Шаблон партнёра не компилируется gen-l10n как есть:** ключи `UNeedHelp`, `TowConfirmDesc` (заглавная буква) и `inventoryEquipped@description` недопустимы как имена Dart-методов (проверено по исходнику `_isValidGetterAndMethodName` во flutter_tools). `validate` и `check` сообщают об этом; `check_gen_l10n.sh` с `DROP_INVALID_TEMPLATE_KEYS=1` позволяет проверить переводы в обход. Исправлять нужно в шаблоне.
- `machine_translation_suspect` без LLM находит только грубые случаи. Смысловые ошибки («Брак» → «Заңға бағынушылық») остаются на LLM и человеке.
- Орфография по частотам не видит ошибок в редких словах. Если подключить словарь через `--vocab`, покрытие вырастет.
